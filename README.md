# GitCount

GitCount 是一个基于 .NET 10 / WPF 的 Windows 桌面工具，用来统计一个或多个 Git 项目的提交数据，支持两种相互独立的模式：

- 本地模式：通过本机 Git CLI 读取本地仓库，不上传代码或统计数据。
- 线上模式：通过 GitLab REST API 直接读取服务器上的提交，不需要克隆仓库，也不需要安装 Git。

两种模式分别保存自己的项目列表，可以在左侧随时切换。

## 功能

- 添加任意数量的 Git 仓库，左侧勾选后一起汇总统计。
- 添加任意数量的 GitLab 线上项目，无需本地仓库，适合直接统计服务器上的提交。
- 按人员查看提交次数、新增行数、删除行数、净变化和变更文件数。
- “提交详情”页可选择任意贡献者，查看其每次提交的新增/删除行数柱状图和逐条提交明细。
- “分项目统计”页分别查看每个项目的汇总数据，以及项目内每位贡献者的明细。
- 支持全部时间、最近 7 / 30 / 90 天、今年和自定义日期范围。
- 默认统计当前分支，也可以勾选“所有分支”。
- 支持过滤大提交：单次提交涉及文件数达到阈值（默认 20），或新增行数超过阈值（默认 500）时，该次提交仍计入提交次数，但新增和删除行数不计入汇总；两个阈值可在界面修改，也可关闭过滤。
- 支持拖入仓库文件夹批量添加项目。
- 支持统计过程中取消，以及将完整结果导出为 UTF-8 CSV。
- 自动保存项目列表、勾选状态和最近一次筛选条件。
- GitLab 访问令牌使用 Windows DPAPI 按当前用户加密保存，不会以明文写入配置文件。

## 运行

如果目标电脑没有安装 .NET 10，直接复制并运行自包含版：

```text
dist\win-x64-self-contained\GitCount.exe
```

发布目录中有两个版本：

- `dist\win-x64\GitCount.exe`：框架依赖版，约 360 KB，目标电脑必须安装 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)。
- `dist\win-x64-self-contained\GitCount.exe`：自包含单文件版，约 65 MB，已包含 .NET 运行时，目标电脑无需安装 .NET，推荐用于分发。

两个版本都支持本地模式和线上模式。本地模式仍然需要：

1. Windows 10/11 x64。
2. [Git for Windows](https://git-scm.com/download/win)，并确保 `git` 命令在 PATH 中。

线上模式不需要 Git，也不需要本地仓库；只需要能够访问 GitLab 服务器，以及一枚具有 `read_api` 权限的访问令牌。

## 使用

1. 在左侧选择“本地模式”或“线上模式”。
2. 本地模式点击“添加项目”选择 Git 仓库根目录，或把仓库文件夹直接拖进窗口；线上模式点击“GitLab 项目管理”，填写 GitLab 根地址和访问令牌，连接后勾选需要统计的项目。
3. 在左侧勾选需要参与汇总的项目。
4. 选择时间范围和分支范围；如需排除大提交，确认“过滤大提交”已勾选并调整文件数、新增行数阈值，然后点击“开始统计”。
5. 在“人员汇总”查看跨项目的人员数据，在“分项目统计”查看单项目数据。
6. 在“提交详情”选择贡献者，柱状图按时间展示每次提交的新增/删除行数，下方表格可查看提交时间、项目、Hash 和提交信息。
7. 需要表格数据时点击“导出 CSV”，导出内容包含人员汇总、项目汇总、项目内人员明细和逐次提交明细。

GitLab 根地址可以填写 `http://gitlab.example.com` 或 `http://gitlab.example.com/gitlab`，程序会自动补全 `/api/v4`。访问令牌只需要 `read_api` 权限，不要授予写权限。

## 统计口径

### 本地模式

- 使用 `git log --no-merges --numstat` 读取数据，合并提交不计入，避免重复统计。
- 新增/删除行数来自 Git 的 `numstat` 结果；二进制文件不产生行数，但会计入变更文件数。
- 作者优先按邮箱分组；没有邮箱时按作者名分组。
- 逐次提交明细保留提交 Hash、提交信息、时间、所属项目以及该次提交的新增/删除行数。
- 启用大提交过滤时，命中提交会在明细中标记“已过滤”，悬停可查看原始行数和过滤原因；顶部汇总、人员汇总、项目汇总和 CSV 均使用过滤后的计入行数。
- 默认只统计当前分支；勾选“所有分支”后使用 `git log --all`。
- 日期按本机日期传给 Git 的 `--since` / `--until`，结束日期包含当天。

### 线上模式

- 使用 GitLab REST API 读取项目提交，默认读取项目默认分支；勾选“所有分支”后请求所有分支。
- 使用提交的 `parent_ids` 排除合并提交，与本地模式的 `--no-merges` 口径一致。
- 新增和删除行数来自 GitLab 提交统计；变更文件数通过提交 diff 接口补查，提交较多时会比本地模式慢一些。
- 线上模式同样支持时间范围、分支范围以及“文件数 / 新增行数”大提交过滤，过滤后的提交仍计入提交次数，但新增和删除行数不计入统计。
- 线上结果取决于 GitLab 账号权限和 API 返回的数据；令牌失效、项目无权限或服务器不可达时，可在“分项目统计”中查看具体错误。

## 数据位置

本地项目、线上项目、当前模式、筛选条件和加密后的 GitLab 令牌保存在：

```text
%LOCALAPPDATA%\GitCount\state.json
```

程序不会修改被统计的仓库。

GitLab 令牌使用 Windows DPAPI 的当前用户范围加密，因此：

- 配置文件里不会出现令牌明文。
- 配置文件复制到其他 Windows 用户或其他电脑后，令牌无法解密，需要重新填写。
- 如果令牌曾经在聊天、日志或截图中暴露，应立即在 GitLab 中撤销并重新创建，只授予 `read_api` 权限。

线上模式会携带令牌访问配置的 GitLab 地址。正式使用时建议使用 HTTPS；如果只能使用 HTTP，请确认服务器位于可信内网，并避免在不可信网络中传输令牌。

## 构建与发布

```powershell
dotnet build
powershell -ExecutionPolicy Bypass -File .\publish.ps1
```

框架依赖版（体积小，开发机已安装 .NET 时使用）：

```text
dist\win-x64\GitCount.exe
```

自包含版（无需目标电脑安装 .NET，推荐分发）：

```powershell
powershell -ExecutionPolicy Bypass -File .\publish-self-contained.ps1
```

输出：

```text
dist\win-x64-self-contained\GitCount.exe
```

首次进行自包含发布时，需要联网下载 .NET 10 x64 运行时包；下载后会缓存到本机 NuGet 缓存，后续可离线发布。

仓库中的 `NuGet.config` 清空了外部包源，便于在无网络环境构建这个无第三方依赖的项目。
